# Scoped catalog freshness review

`POST /api/integrations/freshness/inventory`, `/review`, and `/status` form a separate service boundary for a reviewed local workflow. Existing proposal/publication credentials do not gain this scope.

Configure `MERCADO_FRESHNESS_GRANTS_JSON` only after owner approval: normal managed coordinator token hash, identity, exact collections, `expiresAt:null`, and `freshnessPolicy:"mercado-freshness-v1"`. The associated authority must currently allow `mercado:review:freshness`; wallet-required authorities must sign the changed credential/scope. No grant is created by deployment. Current authority is checked before reads, before writes, and before accepting a result. An accepted in-flight write may finish during revocation; reconcile its durable receipt after access is restored rather than inventing an outcome.

Inventory accepts an optional `cursor` and returns at most 100 active/nondeleted items. It omits vendor identities and excludes asking prices from the price field. Exact PostgreSQL `revision` strings must be preserved without timestamp rounding. `vendor_maintained` and `manual_override` identify records that cannot be updated automatically. Existing `save_product` history conservatively counts as a manual override.

Review accepts only `{operationId,itemId,expectedRevision}`. It never accepts caller/model price, availability, URL or arbitrary field changes. A reviewed server-owned supplier adapter fetches the current source. The first adapter supports the existing pinned Shopify suppliers with exactly one variant and a matching title/handle, region, currency basis and unchanged reference price. It may refresh supplier availability. Price differences, tax/from-price ambiguity, missing evidence, redirects, multiple variants, vendor/manual changes and unsupported suppliers are held. `price_checked` is not changed; this first policy does not claim price/tax revalidation. The local freshness state must track stock validation separately and must not promote stock-only evidence to full price verification.

The atomic update rechecks revision, ownership, active/deleted state, reference-price kind and manual history. An operation receipt and product audit entry commit together using the existing audit table; no schema migration is needed. Status accepts `{operationId}` and returns the same immutable receipt for that source actor. Repeat review with the same ID and input returns the original receipt; changed input conflicts. The caller must preserve uncertain operations and read status, then verify actual changed public catalog values before claiming completion.

Native scheduling, supplier request spacing, freshness state, the one-owner-email outbox and pause/revocation admission are implemented by the local AI host, not by these endpoints. Code deployment alone is not source enrollment, native installation, scheduling or end-to-end acceptance. Keep the original schedule active until the actual native bounded run is verified, then pause the exact unchanged source schedule before enabling its replacement.

Validation: `node --test tests/*.test.mjs`; `node --env-file=../marcada/.env.local scripts/test-freshness-sql.mjs` tests the actual SQL in transaction-local tables and leaves production records unchanged.
